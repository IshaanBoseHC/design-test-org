# Design: Demo GitHub Pull Requests for Terraform Remediation Prototype

**Date:** 2026-03-03
**Author:** Claude
**Status:** Approved

## Overview

Create two demo GitHub pull requests for the HDS prototype repository that showcase Terraform drift detection and security hardening workflows. These PRs will be used for internal demos and will remain open indefinitely without being merged.

## Goals

1. Provide realistic, clickable PR examples for the "View all pull requests" feature in the prototype
2. Demonstrate authentic Terraform remediation scenarios with proper GitHub formatting
3. Keep demo infrastructure completely isolated from the Ember application code
4. Follow the GitHub PR wireframe format provided in `hdsproto/designref/Pull Request #142 - GitHub Wireframe.png`

## Repository Structure

### New Directory Layout

```
hdsproto/
├── hdsproto/              # Ember app (unchanged)
├── terraform/             # NEW - Demo infrastructure
│   ├── aws/
│   │   ├── s3.tf
│   │   ├── iam.tf
│   │   ├── security_groups.tf
│   │   ├── kms.tf
│   │   └── variables.tf
│   └── README.md          # Marks files as demo-only
├── .gitignore             # Updated to exclude Terraform state
└── docs/
    └── plans/
```

### Safety Measures

- All Terraform files isolated in `terraform/` directory at root level
- Clear separation from `hdsproto/` Ember application
- `.gitignore` excludes `.terraform/`, `*.tfstate`, `*.tfstate.backup`, `*.tfplan`
- README.md in terraform/ explicitly warns: "Demo infrastructure - DO NOT APPLY"
- No functional impact on Ember app

## Pull Request Designs

### PR #1: Drift Reconciliation

**Branch:** `fix/drift-reconciliation`
**Title:** `fix(drift): reconcile state and configuration for affected resources`

**Commit Strategy:**
1. Initial commit: Add baseline Terraform infrastructure
2. Fix commit: Apply drift corrections with detailed message

**Files Modified:**
- `terraform/aws/s3.tf` - Enable versioning, add encryption
- `terraform/aws/iam.tf` - Update policy to match actual state

**Changes:**
- Enable S3 bucket versioning (disabled in cloud state)
- Add missing server-side encryption configuration
- Update IAM policy to reflect permissions actually in use
- Add lifecycle rules that were manually configured

**PR Description Sections:**
1. **What was corrected** - Bullet list of specific drift items
2. **Why this change was made** - Context about drift detection scan
3. **Drift Analysis** - Technical details and impact assessment
4. **Remediation Checklist** - Table with Resource | Issue | Remediation | Status
5. **Testing & Validation** - Terraform plan summary
6. **Additional Context** - Links to documentation

### PR #2: Security Hardening

**Branch:** `security/hardening-controls`
**Title:** `security(hardening): apply missing security controls to vulnerable resources`

**Commit Strategy:**
1. Initial commit: Add baseline Terraform infrastructure (same as PR #1 baseline)
2. Security commit: Apply hardening measures with detailed message

**Files Modified:**
- `terraform/aws/security_groups.tf` - Tighten ingress rules
- `terraform/aws/kms.tf` - Add KMS key and encryption policies
- `terraform/aws/s3.tf` - Enable encryption at rest with KMS

**Changes:**
- Remove overly permissive 0.0.0.0/0 security group rules
- Add KMS encryption keys for S3 buckets
- Enable encryption at rest with customer-managed keys
- Add required security and compliance tags
- Implement least-privilege security group configurations

**PR Description Sections:**
1. **What was secured** - Bullet list of security improvements
2. **Why this change was made** - Security scan findings and risk context
3. **Security Remediation** - Detailed technical explanation with CIS/NIST references
4. **Remediation Checklist** - Table with Resource | Vulnerability | Fix | Status
5. **Testing & Validation** - Terraform plan summary, no breaking changes
6. **Additional Context** - CVE references (fictional), AWS security best practices links

**Labels:** [drift-detection|security], automated-fix, terraform

## Implementation Workflow

### Phase 1: Setup Infrastructure Files

1. Create `terraform/` directory structure
2. Write realistic AWS Terraform configurations:
   - S3 buckets with standard configurations
   - IAM policies and roles
   - Security groups with network rules
   - KMS keys for encryption
   - Variables file for configuration
3. Add comprehensive `.gitignore` for Terraform
4. Create README.md with demo warning

### Phase 2: Create Drift PR

1. Create branch `fix/drift-reconciliation` from master
2. Commit baseline Terraform files
3. Modify files to show "before" state (configurations with drift)
4. Commit fixes with title: `fix(drift): reconcile state and configuration for affected resources`
5. Push branch to GitHub
6. Use `gh pr create` to open PR with formatted description
7. Verify PR displays correctly with diffs

### Phase 3: Create Security PR

1. Create branch `security/hardening-controls` from master
2. Commit baseline Terraform files (same starting point as drift PR)
3. Modify files to show security vulnerabilities
4. Commit hardening with title: `security(hardening): apply missing security controls to vulnerable resources`
5. Push branch to GitHub
6. Use `gh pr create` to open PR with formatted description
7. Verify PR displays correctly with diffs

### Phase 4: Validation

1. Confirm both PRs visible on GitHub
2. Verify PR descriptions render correctly with tables and formatting
3. Check file diffs show meaningful changes
4. Test links from prototype UI to PRs work
5. PRs remain open for demo purposes

## Technical Details

### Terraform Configuration Style

- Use realistic AWS resource names (e.g., `app-data-bucket`, `user-service-logs`)
- Include proper tags: `Environment`, `ManagedBy`, `SecurityLevel`
- Follow HashiCorp HCL style guide
- Use variables for configurable values
- Include inline comments explaining configurations

### GitHub CLI Commands

```bash
# PR #1
gh pr create \
  --base master \
  --head fix/drift-reconciliation \
  --title "fix(drift): reconcile state and configuration for affected resources" \
  --body-file .github/pr-templates/drift-pr-body.md

# PR #2
gh pr create \
  --base master \
  --head security/hardening-controls \
  --title "security(hardening): apply missing security controls to vulnerable resources" \
  --body-file .github/pr-templates/security-pr-body.md
```

## Non-Goals

- ❌ Actually applying Terraform configurations (no `terraform apply`)
- ❌ Creating real cloud infrastructure
- ❌ Merging PRs into master
- ❌ Modifying any Ember application code
- ❌ Setting up CI/CD pipelines for Terraform
- ❌ Implementing actual drift detection logic

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Terraform files accidentally applied | Add prominent README warning, use fake resource names |
| Merge conflicts with app code | Isolated directory, different file types |
| Confusion about demo vs. real PRs | Clear commit messages, branch names indicate purpose |
| Breaking Ember build | No overlap in file paths or dependencies |
